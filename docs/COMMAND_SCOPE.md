# 0.4.0 기초 명령 전달 (시험 구현)

상태: **참조 작업 반영 후 검색·구조 탐색과 박스 생성·복제를 추가했습니다. 전체 자동 검사 124개가 통과했고 실제 SketchUp 모델 API·Undo·카메라 확인은 남아 있습니다.** 0.3.1의 읽기 전용 도구를 기반으로 대상이 명확한 짧은 명령을 추가했습니다.

## 첫 구현 범위

| 영역 | 구현 도구 | 기능 |
|---|---|---|
| 선택 | `sketchup_set_selection` | 조회한 객체 ID로 선택 교체·추가·제거·해제 |
| 화면 | `sketchup_set_view` | 위·앞·오른쪽·등각 보기 |
| 화면 | `sketchup_zoom` | 선택 객체 또는 모델 전체가 화면에 들어오도록 확대 |
| 객체 속성 | `sketchup_update_entity_properties` | 그룹/컴포넌트 이름, 자체 숨김·잠금, 기존 태그·재질 지정 및 직접 재질 해제 |
| 이동 | `sketchup_move_entities` | 그룹/컴포넌트를 모델 축 기준 mm 상대 이동 |
| 생성 | `sketchup_create_box` | 모델 축 mm 원점·치수로 독립 박스 그룹 생성 |
| 복제 | `sketchup_duplicate_entities` | 명시한 그룹/컴포넌트를 하나씩 복제하고 모델 축 mm 상대 이동 |
| 결과 확인 | `sketchup_get_command_result` | 명령 ID로 완료/실패와 변경 전후 정보 조회 |

박스 외 임의 형상 생성·개체 삭제·폭파, 면/선 직접 이동, 회전·축척, 재질/태그 신규 생성, 파일 열기·저장·내보내기, 임의 Ruby 실행, 임의 메뉴/키보드 명령 전달은 후속 단계로 둡니다. 기본 동작은 이름과 인수가 정해진 SketchUp API 명령으로 전달합니다.

생성·복제의 치수 제한과 속성 보존, 생성된 ID의 사용은 [CREATION_COMMANDS.md](CREATION_COMMANDS.md)에 있습니다.

## 검색 결과와 명령 연결

[객체 검색·구조 탐색](ENTITY_DISCOVERY.md)의 `persistent_id`와 `parent_path`를 대상 ID와 예상 편집 경로로 사용할 수 있습니다. 명령 직전 현재 편집 경로를 다시 확인해야 합니다. `in_current_context=false`인 객체를 찾았다고 해서 명령이 자동으로 부모 내부로 들어가지는 않습니다. 공유 정의 내부의 객체는 동일 PID가 여러 배치 경로에 나타날 수 있으므로 PID만으로 위치를 추측하지 않습니다.

## 대상 및 권한

- 모든 명령에 현재 `session_id`, `model_id`, 재사용하지 않는 `command_id`를 지정합니다.
- 객체는 직전 조회에서 받은 영구 ID와 편집 경로로 지정합니다. 이름이나 현재 선택만으로 암묵적인 대상을 정하지 않습니다.
- 명령 실행 전에 모델 ID, 현재 편집 경로, 객체 유효성·소속, 잠금 상태를 재확인합니다. 잠긴 객체의 이름/이동/태그/재질 변경은 거부하고, 명시적인 잠금 해제 명령만 허용합니다. 잠긴 상위 객체의 내부 변경도 거부합니다.
- 화면/선택을 포함한 모든 변경 명령은 해당 SketchUp 패널의 로컬 실행 허가와 유효한 lease가 필요합니다. 기존 정보 조회에는 허가를 요구하지 않습니다.
- 첫 버전은 현재 편집 컨텍스트 안의 그룹/컴포넌트 최대 25개를 처리합니다. 편집 경로를 자동으로 열거나 닫지 않습니다.
- 태그·재질은 모델에 이미 존재하는 정확한 이름으로 확인합니다. 없거나 모호하면 거부하며 새 항목을 자동 생성하지 않습니다.

## 실행과 결과

1. 입력·대상·권한·예상 컨텍스트를 검증합니다.
2. 모델 변경 명령은 `dry_run`으로 대상 수, 예상 속성 변경 또는 모델 축 이동량을 미리 확인할 수 있게 합니다.
3. 인스턴스별 명령을 직렬화하고 SketchUp 메인 스레드에서 실행합니다. 대기 중 모델/권한/기한이 달라지면 실행하지 않습니다.
4. 이름·태그·재질·숨김·잠금·이동·박스 생성·복제는 한 요청을 한 `start_operation`/`commit_operation`으로 묶고 오류 시 `abort_operation`으로 되돌립니다. 사용자가 SketchUp에서 한 번의 Undo로 취소할 수 있게 합니다.
5. 선택·카메라 변경은 모델의 Undo 기록과 별개로 취급하고 변경 전 UI 상태를 결과에 포함합니다. 모델 변경의 Undo 보장과 혼동하지 않습니다.
6. 응답에는 명령 ID, 대상 모델/객체, 실행 시각, 변경 전후 값 또는 이동 후 외곽 좌표를 반환합니다. 성공 응답 전 결과를 메모리에 보관합니다.

완료·실패·결과 불명·미리보기 결과는 세션 메모리에 최근 32개까지 보관합니다. `command_id`는 `sketchup_get_instance`의 `state.next_command_id`로 받은 `session_id:연속번호`를 사용합니다. 같은 ID에 다른 내용이 오면 거부하고 같은 내용은 결과만 반환합니다. 캐시에서 사라진 이전 번호는 `command_expired`이며 다시 실행하지 않습니다. 모델 전환·권한 회수·GUI 재연결은 번호와 이력을 유지하고, Ruby Session이 새로 만들어지면 새 세션 ID를 사용합니다.

`expected_context`는 직전 `sketchup_get_selection_info` 또는 모델 요약의 `data.edit_context.path`에서 `persistent_id` 문자열을 순서대로 추출한 배열입니다. 루트 편집은 `[]`이며 `path_truncated=true`이면 진행하지 않습니다. 객체 대상은 조회한 ID를 명시해야 하며 현재 선택을 암묵적으로 사용하지 않습니다.

실행기에 전달된 명령은 검증 실패나 `dry_run`도 ID를 소비합니다. 권한·기한·모델·순서·작업 중 여부 등의 세션 검사에서 거부한 요청은 소비하지 않습니다. 미리보기 후 실제 실행에는 새 ID가 필요합니다. 결과는 `result.state`에 `preview`, `completed`, `failed`, `unknown`을 반환하며 성공 여부와 함께 확인합니다. 속성·이동 결과는 변경 전후 속성 또는 모델 축 원점 좌표를 담습니다. 한 MCP 연결이 제어를 사용 중이면 다른 연결의 변경을 거부합니다.

시간 초과·연결 끊김으로 결과가 불명확하면 자동 재전송하지 않습니다. 결과 이력 또는 모델 상태를 다시 조회하고, 결과를 확인할 수 없는 경우에는 상태 불명을 명시합니다. 짧은 동기 명령은 실행 중 강제 중단이 가능하다고 약속하지 않습니다.

## 이동 기준

`delta_mm=[dx,dy,dz]`를 모델 축 방향 상대 이동으로 정의합니다. 중첩 편집 중에는 편집 변환을 고려해 부모 좌표계로 변환합니다. 비균등 축척·회전·반전된 부모 안의 이동도 모델 축 기준으로 같은 결과가 나와야 합니다. 역변환 불가능한 컨텍스트는 거부합니다. 컴포넌트 정의 내부 형상을 바꾸지 않고 선택한 배치만 이동합니다.

## 실제 앱에서 남은 완료 기준

1. 공통 명령 검증·허가·ID/결과 이력·중복 실행 방지.
2. 선택 → 화면 보기/확대: 정확한 모델·편집 경로 및 상태 결과 확인.
3. 이름·숨김·잠금 → 기존 태그/재질: 실제 모델에서 변경과 Undo 확인.
4. 박스 생성·그룹/컴포넌트 복제: 원본 유지, 정확한 치수/배치, 실패 시 새 객체 제거 및 한 번의 Undo 확인.
5. 그룹/컴포넌트 이동: 회전·반전·비균등 축척된 부모, 다중 선택, 잠금 거부 및 Undo 확인.

예시 확인 요청은 “조회한 그룹을 선택해줘”, “선택한 객체를 확대해줘”, “이 그룹 이름을 A동으로 바꿔줘”, “이 그룹을 모델 X 방향으로 1,000 mm 이동해줘”입니다. 다른 모델/컨텍스트, 오래된 ID, 허가 회수, 중복 요청, 시간 초과 상황에서 엉뚱한 객체나 모델을 변경하지 않는지도 필수로 검사합니다.
