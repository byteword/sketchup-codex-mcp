# SketchUp / ChatGPT 실기 검증

## 0.4.0 객체 검색·구조 탐색 추가

새 GUI·MCP·RBZ를 함께 사용하고 MCP 도구 **17개**를 확인합니다. 아래 실모델 검증은 아직 진행하지 않았습니다.

| 시험 | 성공 기준 |
|---|---|
| 사용자 제어에서 이름·정의 이름·태그·종류 검색 | 허가 없이 조회, 한글/영문 대소문자 조건 및 정확한 직접 태그 일치 |
| 중첩된 그룹의 하위 조회 | 전체 parent_path를 사용해 올바른 하위 객체 반환, 편집 위치 유지 |
| 같은 정의를 두 위치에 배치 | 같은 자식 PID도 서로 다른 instance_path로 반환 |
| 현재 편집 위치 / 모델 전체 범위 | root_path와 in_current_context가 실제 위치와 일치 |
| limit=1 및 next_cursor 반복 | 누락·중복 없이 이어 조회, 빈 페이지도 커서가 있으면 계속 조회 |
| 깊이 제한 / 모델 구조 변경 | omitted.depth 및 complete 확인, 구조 변경 후 처음부터 다시 조회 |
| 검색 결과로 기존 명령 실행 | 현재 편집 위치의 대상만 명시해 선택·이동, 중첩 경로 자동 진입 없음 |
| 조회 전후 비교 | 모델 수정 상태·선택·카메라·편집 경로·Undo 유지 |

자세한 계약과 예시는 [객체 검색·구조 탐색](ENTITY_DISCOVERY.md)에 있습니다.

## 0.4.0 명령 전달: 설치 후 확인할 항목

저장된 시험 모델에서 GUI·MCP·RBZ를 함께 0.4.0으로 교체하고 SketchUp 및 MCP 연결을 다시 시작합니다. 두 EXE의 파일 버전 `0.4.0.0`·제품 버전 `0.4.0`, 패널 버전 `0.4.0`, MCP 도구 17개를 확인합니다. 아래 항목의 실제 실행은 아직 완료하지 않았습니다.

선택 상세를 조회해 대상 영구 ID와 `edit_context.path`의 순서 있는 `persistent_id` 배열을 확인합니다. 각 명령 직전 상태 조회의 `next_command_id`를 사용하고, 미리보기와 실제 실행에는 서로 다른 ID를 사용합니다.

| 시험 | 성공 기준 |
|---|---|
| 사용자 제어 상태에서 조회 / 변경 | 조회는 성공, 변경은 권한 거부 |
| 패널에서 MCP 명령 실행 허용 후 `dry_run` | 예상 변경만 반환, 모델·선택·화면·Undo 유지 |
| 선택 교체·추가·제거·해제 | 지정한 그룹/컴포넌트에만 적용, 기존 Undo 기록 유지 |
| 위·앞·오른쪽·등각 / 모델·지정 객체 확대 | 모델 축 기준 보기와 확대, 선택·모델 데이터 유지 |
| 이름·숨김·잠금·기존 태그/재질 변경 | 요청 속성만 변경, 요청당 한 번 Undo로 모든 대상 복구 |
| 직접 재질 해제 / 잠금 해제 | material=null 동작, 잠긴 객체는 별도 잠금 해제 후 변경 |
| 모델 축 X/Y/Z 이동 | 입력 mm와 결과 원점이 일치, 한 번 Undo로 복구 |
| 회전·반전·비균등 축척된 부모 내부 이동 | 모델 축 이동량 일치, 공유 정의/잠긴 상위 컨텍스트는 거부 |
| 오래된 모델·편집 경로·없어진 객체 | 실행 전 거부, 다른 모델/객체에 변경 없음 |
| 같은 명령 재전송 / 다른 내용으로 ID 재사용 | 결과 재조회만 수행 / 충돌 거부 |
| 결과 32개 초과 후 오래된 ID | command_expired, 재실행 없음 |
| 모달 지연·기한 초과·연결 종료 | 자동 재전송 없음, 결과 이력 조회 후 상태 판단 |
| 두 MCP 연결 / 권한 회수 / 모델 전환 | 다른 소유자 명령 거부, 회수 이후 새 변경 거부 |
| 선택/카메라 변경 중 오류 | 이전 UI 상태 복구 또는 결과 불명 명시 |

아래는 이전 버전의 확인 항목과 당시 실행 상태입니다. 조회 회귀 항목은 0.4.0에서도 확인합니다.

## 0.3.1 실행 파일 버전 확인

`SketchUpMcp.exe`, `SketchUpPipeProbe.exe` 각각의 Windows 속성 → 자세히에서 파일 버전 `0.3.1.0`, 제품 버전 `0.3.1`, 제품명 `SketchUp Local MCP Bridge`를 확인합니다. 파일 설명은 각각 `SketchUp MCP Adapter`, `SketchUp MCP Bridge`입니다. `SketchUpMcp.exe --version`, GUI 제목, MCP 초기화/상태, SketchUp 패널도 `0.3.1`이어야 합니다. 패키징 시 이 중 EXE 리소스와 C#/Ruby 버전 일치는 자동 검사합니다.

## 0.3.x 조회 기능: 설치 후 확인할 항목

GUI·MCP 어댑터와 RBZ를 모두 0.3.1로 교체하고 SketchUp 및 MCP 연결을 다시 시작합니다. 현재 실행 중인 모델은 먼저 저장하세요. 패널 버전 0.3.1과 MCP 도구 9개를 확인합니다.

| 시험 | 성공 기준 |
|---|---|
| 제어권을 user로 두고 모델 요약 | 별도 작업 허가 없이 현재 파일명·단위·mm 외곽 크기 조회 |
| 미저장 빈 모델 | saved=false, path="", 빈 bounds/0개 선택 |
| 그룹 하나 선택 | 이름·태그·재질·잠금 상태가 엔티티 정보와 일치 |
| 아무것도 선택하지 않음 | 오류 없이 items=[] / total=0 |
| 면·선·컴포넌트 혼합 선택 | 지원 필드만 반환하고 타입별로 조회 성공 |
| 회전하고 비균등 축척한 그룹 | definition_bounds는 원래 크기, instance_axis_lengths_mm은 축척 반영, model_bounds는 모델 축 크기 |
| 축척·회전된 부모 안을 열고 자식 선택 | 상위 변환을 포함한 mm 치수·현재 편집 경로 |
| 재질 없는 자식/숨긴 부모의 자식 | 직접 할당/자체 상태로 표시하며 유효 외관으로 잘못 해석하지 않음 |
| 25개 이상 선택 | next_offset으로 나머지 조회; 선택 변경 시 처음부터 조회 |
| 조회 사이 새 모델 열기 | 이전 model_id는 model_mismatch, 새 목록 갱신 후 성공 |
| 20,000개를 넘는 루트 | 제한 시 complete=false, 전체 total과 조사 scanned 구별 |
| 조회 전후 비교 | 선택·씬·모델 수정 상태·Undo 기록이 조회 때문에 변하지 않음 |

컴포넌트 정의의 영구 ID는 SketchUp 2019에서 null일 수 있습니다. 모델 편집이나 임의 코드 실행 도구는 추가하지 않았습니다.

## 기존 0.2.0 연결/작업 회귀 항목

0.1.1 기본 연결은 사용자 성공 보고가 있습니다. 아래 0.2.0 검사는 아직 실행 결과를 기록하지 않았습니다. 처음에는 빈 모델 두 개로 시험합니다.

| 순서 | 시험 | 성공 기준 |
|---|---|---|
| 1 | `start.cmd` 실행 | C# 빌드 성공, GUI에 Listening 표시 |
| 2 | RBZ 설치, 메뉴 실행 | 패널에 Ruby/SketchUp/64bit 표시, Fiddle 오류 없음 |
| 3 | 연결 버튼 | GUI에 올바른 PID, 세션, 모델 경로 표시 |
| 4 | 양쪽 Ping | GUI→SU, SU→GUI 한글이 동일하게 왕복 |
| 5 | 두 개 이상 인스턴스 연결 | PID별 독립 행, 미저장 동명 모델도 구분 |
| 6 | A만 MCP 허용 | A만 시험 작업 가능, B는 사용자 제어 |
| 7 | A/B 각 허용 후 시험 작업 | 양쪽 진행률 독립 증가, 화면 회전 가능 |
| 8 | A의 중지 버튼 | A만 취소, 사용자 제어 복귀, B는 계속 진행 |
| 9 | GUI에서 B 중지 | B 취소. GUI 취소는 B의 허가 자체를 회수하지 않음 |
| 10 | 오류 표시 시험 | 의도적 오류가 Ruby 패널과 GUI에 표시, 모델 변화 없음 |
| 11 | 작업 중 제어권 회수 | 작업 중지, 새 작업 거부, 재허용은 새 lease |
| 12 | 작업 중 새 모델 열기 | 이전 작업 취소, model_id 변경, 사용자 제어 복귀 |
| 13 | GUI 종료/재실행 | 연결 해제, 작업 폐기, 자동 재연결 후 사용자 제어 |
| 14 | 선택한 SU 종료 | 해당 행 제거, 다른 인스턴스로 선택 자동 전환 안 됨 |
| 15 | Ruby 패널 닫기/다시 열기 | 제어권 사용자 복귀, 패널 정상 복원 |
| 16 | 서버 없이 SU 연결 누르기 | 오류 2 표시, SU 조작 가능, 2초 간격 재시도 |
| 17 | 모달 창 열고 닫기 | 응답 지연 표시 가능, 닫은 뒤 정상 회복 |
| 18 | 20회 연결/해제, 10분 대기 | 크래시·영구 멈춤·비정상 핸들 증가 없음 |

오류가 나면 다음을 함께 기록합니다.

- SketchUp 정확한 버전, 패널의 Ruby 버전/포인터 비트
- Windows 버전, GUI/SketchUp이 같은 계정과 권한 수준인지
- 실패 단계와 동시 인스턴스 수
- 패널 오류 전문과 GUI의 `로그 저장` 파일
- 확장 로딩 자체가 실패한 경우 Ruby 콘솔 오류 전문

자주 볼 오류: `2`는 GUI 미실행/파이프 없음, `5`는 접근 거부, `231`은 연결 가능한 파이프 인스턴스가 아직 없음, `109/232/233`은 연결 종료 관련입니다. `997`(pending), `996`(incomplete)는 내부에서 처리되는 정상 비동기 상태입니다.

로그에는 모델 경로와 세션 정보가 들어갈 수 있습니다. 공개 이슈에 붙일 때 경로에 포함된 개인/업무 이름을 필요한 만큼 가립니다.
