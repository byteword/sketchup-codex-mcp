# 0.4.0 실제 SketchUp 시험 결과 — 2026-10-28

사용자가 실행한 SketchUp에 MCP로 명령을 보내고, 반환값·후속 조회·사용자의 화면 및 Ctrl+Z 확인을 함께 기록했습니다. 자동 검사 124개의 대역 모델 시험과 별개인 실기 기록입니다. 이번 문서 정리에서는 모델 명령이나 자동 검사를 다시 실행하지 않았습니다.

## 환경과 확인 방법

- Windows x64, 실제 SketchUp `19.2.222`, 내장 Ruby `2.5.5`.
- 중개 앱과 Ruby 확장의 보고 버전 `0.4.0`, MCP 도구 19개. 시험 배포 준비 기준 커밋은 `fa3fa30`입니다.
- 처음에는 기존 작업 모델에서 정보 조회·검색·Ping만 수행했습니다. 생성 이후의 변경 시험은 사용자가 새로 연 미저장 시험 모델에서 수행했습니다. 기본 인물 컴포넌트는 남아 있었습니다.
- 명령마다 최신 상태의 `next_command_id`를 사용하고, 선택 조회의 편집 경로를 `expected_context`로 전달했습니다. 시간 초과에 따른 재전송은 하지 않았습니다.
- 아래의 **실행·조회 확인**은 실제 SketchUp API 응답과 후속 읽기 결과입니다. **사용자 확인**은 채팅으로 보고받은 화면/Undo 결과입니다. 스크린샷이나 동영상은 수집하지 않았습니다.

## 중첩 이동의 수치 근거

바깥 그룹의 영구 ID는 `11849`, 선택한 안쪽 그룹은 `11821`이었습니다. 바깥 그룹에는 안쪽 박스 2개가 있었고, 요청 대상은 선택한 1개로 한정했습니다. ID는 이 실행 세션의 추적용이며 재사용할 대상 식별자가 아닙니다.

사용자가 바깥 그룹의 30° 회전과 2배 늘리기를 준비했다고 보고했습니다. 도구가 부모의 회전각·축척 행렬을 직접 노출하지 않으므로 그 수치 자체를 독립적으로 재측정한 결과로 해석하지 않습니다. 중첩 편집 경로, 변환된 치수와 아래 모델 축 좌표의 이동 차이를 조회로 확인했습니다.

| 모델 축 외곽 값 (mm) | 이동 전 | 이동 후 | 차이 |
|---|---|---|---|
| min | `[-15588.457268,0,0]` | `[-14588.457268,0,0]` | `[1000,0,0]` |
| max | `[15000,18588.457268,3000]` | `[16000,18588.457268,3000]` | `[1000,0,0]` |
| size | `[30588.457268,18588.457268,3000]` | `[30588.457268,18588.457268,3000]` | `[0,0,0]` |

외곽은 변환한 경계 상자의 좌표이며 실제 모서리 길이와 같다고 보장하는 값은 아닙니다. 이번 판정은 그 절대 크기가 아니라 이동 전후의 차이를 기준으로 했습니다. 이후 잠금 시험 직전 조회에서 min/max가 이동 전 값으로 복귀한 것을 확인했습니다.

## 시험 종료 상태

선택된 박스는 이름·좌표를 유지했고 잠금은 해제했습니다. 연결은 유지한 채 `authority=user` 상태로 마쳤습니다. 잠금 설정과 해제는 실제 모델 작업이므로 Undo 이력에 남을 수 있으며, 이력을 초기화하거나 파일을 저장하지 않았습니다.

## 남은 실기와 관찰 사항

- Y/Z 방향 이동, 반전·더 깊은 중첩, 다중 대상 이동·복제, 중첩 위치의 박스 생성.
- 컴포넌트 복제의 정의 공유, 그룹 복제본을 실제 편집해 독립성 확인, 속성 사전·태그·재질·숨김·그림자 보존, 솔리드/법선 대조.
- 선택 추가/제거/해제, 전체 모델 확대, 오류 중 카메라·선택 복구, 두 점 투시 등 특수 보기 거부.
- 모든 검색 필터와 반복 커서 조회, 전체 모델의 공유 배치 경로, 조회 전후 수정 상태·Undo 불변의 체계적 비교.
- 공유/잠긴 상위 정의·부착 객체의 거부, 오래된 ID·다른 모델/편집 위치 거부, 이력 만료·중복 요청·응답 지연·연결 끊김·다중 인스턴스/소유자 경합.
- **모델 전환 식별:** 기존 작업 모델에서 새 시험 모델로 바꾼 뒤에도 같은 `model_id`가 보고된 응답이 관찰됐습니다. 이번 시험에서는 제목/빈 파일 경로·편집 경로·대상 객체를 새로 확인했지만, 모델 전환 시 ID 갱신과 이전 모델 ID 거부는 별도 조사·실기 확인이 필요합니다. 모델 격리까지 통과했다고 기록하지 않습니다.

이번 결과는 이 환경과 위 시험 조건의 확인입니다. 전체 [수동 시험 계획](MANUAL_TEST.md) 통과나 정식 릴리스 판정을 의미하지 않습니다. 자동 검사와 패키징 이력은 [검증 범위](VALIDATION.md)에 보존합니다.
