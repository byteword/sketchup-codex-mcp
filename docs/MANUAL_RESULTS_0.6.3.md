# 0.6.3 실제 SketchUp 전체 검사 — 2026-10-28

## 환경과 실행

사용자가 GUI·MCP·Ruby 확장을0.6.3으로 교체하고 작은 미저장 시험 모델에서 MCP 실행 허가를 켰습니다. 실제 SketchUp20.0.363 / Ruby2.5.5 / Windows x64입니다. 도구39개가 직접 연결된 이 채팅에서 최신 세션·모델·명령 ID와 루트 편집 경로를 조회한 뒤 suite=all을 한 번 실행했습니다.

기준 소스는 수정 커밋2296b92입니다. GUI·확장 버전0.6.3과 실행 허가를 조회로 확인했으며, 등록 어댑터는 사용자가0.6.3 패키지로 교체했습니다. 요청과 전후 조회를 [원본 JSON](native-test-0.6.3-2026-10-28.json)에 보관했습니다.

## 결과

**56개 통과(기능55개＋정리1개), 실패0·생략0, passed=true.** Ruby 실행 본문의 duration_ms는48입니다. 전체 채팅·MCP 왕복 시간이나 UI 렌더 시간·CPU 측정값은 아닙니다.

이전0.6.1/0.6.2에서 실패했던 중앙 경로 Follow Me, 컴포넌트 해제 후 raw_group, raw_point_move와 raw_vertex_move가 모두 통과했습니다. 따라서 경로선 정리, 해제 결과 내부 항목 제외, Length 수치 비교 수정이 이번 실제 모델 조건에서 동작함을 확인했습니다.

## 정리와 전후 상태

- cleanup_verified=true, operation_closed=true.
- UI 정책defer, view_redraw_requested=true, inspectors_refresh_requested=true, warnings=[].
- 트레이 표시 변경은false입니다. 실제 렌더 완료나 아웃라이너 CPU 개선을 관찰/측정한 결과로 해석하지 않습니다.
- modified_before=false / modified_after=false. 후속 모델 조회에서도 modified=false.
- 루트 컴포넌트1개, 태그1·재질8·정의1·장면0, 선택0, 루트 편집 경로가 전후 동일합니다.
- 후속 모델의 외곽 min/max/size도 검사 직전과 정확히 일치했습니다. 이번에는0.6.2 후속 진단 때의 외곽 차이 관찰이 반복되지 않았습니다.
- 검사 임시 작업은 abort됐으며 파일을 저장/전환하지 않았습니다.

## 별도 검증과 한계

이번 suite는 한 operation 안에서 임시 변경을 abort합니다. 개별 명령의 Undo와 모델 수명주기, 실제 렌더/Outliner CPU, 아주 큰 모델·깊은 중첩·특수 카메라·다중 사용자 경합을 모두 인증하지 않습니다.

일괄 변경의 중간 실패 전체 취소·후속 성공·사용자의 Ctrl+Z 한 번에 두 박스 제거, 카메라 전용 장면 변경과 미사용 정의 정리는 [0.6.2 별도 실기](MANUAL_RESULTS_0.6.2.md)에 있습니다.0.4.1 New/Open 결과도 당시 버전/환경의 기록입니다. 이 별도 시나리오를 이번0.6.3 실행에서 다시 시험했다고 기록하지 않습니다.

0.6.3 개발 자동 검사229개와 [전체 로그](validation-0.6.3.txt)는 API 대역 회귀입니다. 이번56개 실제 SketchUp API 확인과 구분합니다. 정식 릴리스 태그/원격 CI 성공/SketchUp2019 재검증을 의미하지 않습니다.
