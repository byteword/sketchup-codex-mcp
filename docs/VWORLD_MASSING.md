# SITE 주변 건물 높이 → 원본 윤곽 매스

사용자는 대략적인 배치 확인을 위한 휴리스틱을 허용했다. 아래는 현재 구현의 보수적인 기준이며, 높이 0값 원인·매칭 허용치·저장 경로를 조정할 [후속 과제](VWORLD_MASSING_NEXT.md)를 별도로 기록했다.

2026-10-30 실제 `261023_대지` 모델에서 수유동 53-25·53-26을 기준으로 실행했다. 원본 SITE/3D Block을 보존하고 최상위 **VWorld_SITE50m_건물매스_18동** 그룹(PID `200562`)에 18개 솔리드를 만들었다. Z=0 원본 면을 그대로 수직으로 올렸으며 지형 표고를 새로 적용한 것은 아니다. 생성은 하나의 Undo 작업이다. 모델 파일 저장은 사용자가 수행한다.

## 이번 결과

| 항목 | 결과 |
|---|---:|
| SITE 경계에서 50m 안에 닿는 원본 건물 윤곽 | 59개 |
| 대응과 높이가 확인되어 생성 | 18동 |
| 대응됐지만 높이 0/미제공 | 34개 |
| 대응 불확실 | 7개 |
| 생성 높이 범위 | 6.7~28.75m |
| 두 필지와 모델 SITE의 모서리 정합 RMS | 2.503mm |

외곽 일부가 50m 안에 들어오면 그 건물 전체 윤곽을 대상으로 한다. 중심점 기준 50m나 SITE 중심에서 50m가 아니다. WFS 조회는 이 영역을 감싸는 사각 범위이므로 원자료는 79건이며, 원본 윤곽을 정확한 경계 거리로 다시 걸렀다. 원자료 `hg=0`은 실제 0m로 해석하지 않는다. 높이 없는 건물을 층수나 이웃 평균으로 자동 추정하지 않는다.

정합은 WGS84 지역 접평면을 사용하고 X 동쪽/Y 북쪽/mm 축척을 고정한 평행이동이다. 양 필지의 네 극점과 모델 네 모서리를 대응하며 최대 오차 500mm를 넘으면 중단한다. 실제 측량 정확도를 2.5mm로 보장하는 의미는 아니다. 위치/높이 데이터 자체의 갱신시점과 정확도는 별도다.

매칭은 원본 면과 VWorld 폴리곤의 삼각분할 교차면적으로 판정한다. 원본 면 덮임 45% 이상, IoU 25% 이상, 다음 후보 IoU가 최상위의 65% 미만이어야 한다. 이번 18동의 덮임은 약 67.8~95.4%, IoU는 약 56.1~94.2%다. 하나의 API 건물을 여러 원본 면에 중복 적용하거나 구멍 있는 원본 면을 자동 처리하지 않는다. 원본 면의 오목한 윤곽은 그대로 유지한다.

## 반복 실행

등록·활성화된 기법:

- `user / geo.footprint-scan`: SITE 경계 거리로 원본 면 윤곽 추출.
- `user / geo.vworld-massing`: 실제 원본 스냅샷과 매칭 당시 좌표가 일치하는지 확인한 뒤 수직 매스 생성. 변경된 소스는 거부하며 각 동의 솔리드/높이/XY bounds를 검사한다.

`workflows/suyu-site-50m.json`에 현재 모델의 SITE/3D Block 경로와 두 PNU, 50m 반경, 기존 흰색 재질을 저장했다. 다른 모델에 이 경로를 그대로 적용하지 말고 SITE·소스 경로와 PNU를 바꾼다. 모델 최상위 편집 상태에서 사용한다. VWorld 키는 Probe AddOns에서 등록하고 활성화해야 한다.

프로젝트 폴더의 PowerShell에서 먼저 조회·계획만 실행한다:

```powershell
.\scripts\Invoke-VWorldMassing.ps1 -Probe 'C:\Users\bytew\OneDrive\문서\sketchup extensions\sketchup-codex-mcp\SketchUpPipeProbe.exe'
```

조회부터 새 그룹 생성까지 실행하려면 같은 명령 끝에 **`-Apply`**를 붙인다. 매번 시간을 붙인 **새 그룹**을 생성하며 기존 결과나 원본을 덮어쓰지 않는다. `-Name '원하는 그룹명'`, `-Config '다른 설정.json'`, `-Python 'python.exe 경로'`를 지정할 수 있다. 다른 PC에서는 Python 3가 필요하다. 현재 작업본은 dist의 임베디드 Python을 자동 사용한다.

스크립트는 MCP 세션/문서/권한/편집 위치를 새로 확인하고, 두 필지 조회 → 좌표 정합 → 건물 조회 → 원본 윤곽 추출 → 면적 매칭 → 고정 수정본 검증/계획 → 선택적 적용을 수행한다. 결과와 실패 사유, 조회 자료, job ID는 `dist/vworld-run-*`에 저장한다. 인증키는 기록하지 않는다. 타임아웃·불확정 적용은 재시도하지 않으며 job/command 결과를 확인해야 한다.

현재 한 번의 범위 조회는 100건 미만, 새 매스 63동 이하, 매칭된 원본의 직접 부모 그룹 4개 이하, 각 스냅샷 2048엔티티 이하로 제한한다. 초과하면 반경을 줄이도록 중단한다. 닫힌 수평 Face가 없는 순수 선 연결, 구멍 있는 면, 여러 면이 한 건물에 대응하는 경우는 별도 정리가 필요하다.

## 검증과 TLS 수정

현재 모델에서 18동 생성이 성공했고 다시 읽은 18동 모두 솔리드·높이 일치였다. 원본 SITE 면/원본 건물 윤곽을 유지했으며 루트 객체 수는 8→9다. 생성 후 화면 PNG로 실제 배치를 확인했다. 반복 스크립트도 새로 조회해서 59개/18동/41개 보류와 같은 계획을 만들었다. 이 재현 검사는 `-Apply` 없이 실행해 중복 그룹을 만들지 않았다.

실제 Probe 0.14.1에서 HTTPS `SecureChannelFailure`가 발생했다. csc 빌드의 기본값이 SSL3/TLS1.0인 것을 확인했고 TLS1.2에서는 공식 API가 정상 응답했다. 이번 작업은 같은 승인 애드온/DPAPI 저장소를 사용하는 읽기 전용 helper로 조회했다. Probe 소스는 0.14.2에서 TLS1.2를 요구하도록 수정했으며 인증서 검증과 redirect 거부는 유지한다. **실행 중인 설치 앱은 자동 교체하지 않았다.** 반복 스크립트의 helper는 현재 0.14.1 설치본에서도 이 문제를 해결한다.

검사: 애드온 60개, 교차면적/오목 윤곽/구멍/중복 대응/높이 결측/정합 거부 Python 8개, 등록 기법 오프라인 4케이스, 실제 생성 18동·121면. 수정된 Probe 서비스 자체의 실제 주소 API 성공도 확인했다. 기존 0.14.1 전체463개 회귀 검사와 별도의 이번 검증이며 0.14.2 전체 재실행으로 표기하지 않는다.

기법 공유용 `dist/vworld-massing.probe-techpack`에는 두 고정 기법이 들어 있다. 원본·매칭·조회 근거와 실제 결과 기록은 `dist/vworld-massing-match.json`, `dist/vworld-native-result.json`, `dist/vworld-massing-native.png`에 있다. 생략 윤곽을 확인하려면 `dist/vworld-massing-inventory.csv`를 참고한다.
