## 발견한 문제와 중단 지점

1. **미저장 모델의 `save_copy`**: native가 `Model must be saved before copying.` 오류를 반환했다. 모델은 처음부터 미저장이었다.0.12.1은 `model_unsaved`로 미리 검사하고 사용자가 한 번 저장하도록 안내한다. 저장된 모델의 복사본 왕복은 아직 미실행이다.
2. **라이브러리 native verify의 복구 불일치**: panel의 정상 케이스들을 임시 생성/abort하는 명령36이 `Library verification cleanup did not restore the model stamp`, `outcome_unknown`을 반환했다. 같은 command ID의 결과 조회로 확인했고 자동 재실행하지 않았다. 이후 읽기에서 루트4개/정의5개/재질10개/태그2개/장면2개, 선택0, 기존 박스/UV 패널과 초기 화면 상태는 확인됐지만, 내부 전후 stamp가 기록되지 않아 차이 원인은 확정할 수 없다. **복구 성공으로 판정하지 않는다.**

0.12.1은 후자의 엄격한 실패 판정을 유지하며 `changed_fields`와 제한된 전후 차이를 cached command result에 넣는다. 일반 계획과 typed 계획 모두 적용한다. bounds가 원인인지, 자원 ID/modified가 달라지는지는 새 진단 결과가 있어야 판단할 수 있다. 진단 추가는 근본 원인 수정이나 native 재시험 통과가 아니다.

검사 진행 중 첫 panel verify 작업은 비동기 제출 완료 전에 다음 명령을 발행해 command_id_conflict로 거부됐다. 이는 검사 호출 순서의 문제이며 모델 변경 없음으로 끝났다. 이후에는 library_job의 종료를 확인한 후 다음 변경을 발행했다. 여러 authoring 예제를 한꺼번에 요청했을 때 byte budget 거부, 잘못된 QA 기법 ID의 스키마 거부도 있었으며 각각 개별 조회/규격 ID로 수정했다.

## 모델과 파일 상태

복구 불일치 확인 뒤 추가 모델 변경은 멈췄다. 원래 Laura와 검사 박스, SKP 복사본, 텍스처 패널이 있다. QA 장면2개/스타일1개/태그1개/재질2개도 검사 중 생성됐다. 불확정 상태에서 자동 삭제하지 않았다. 사용자에게 새 작은 시험 모델 및 로컬 허가를 요청했다. 원래 문서 저장·덮어쓰기·전환은 자동 수행하지 않았다.

출력 파일은 로컬 `dist/native-acceptance-0.12.0-20261029-1932`에 남겨 확인할 수 있다. PNG 입력2개, baseline-display.json, selected-box.skp, box-front.dxf와 native-report.json이다. 미저장 모델 복사본은 생성되지 않았다. 설치 앱은0.12.0을 유지한다. QA 기법 초안5개는 기본 라이브러리의 `qa.native012-*-20261029`이며 활성화하지 않았다.
