# 0.13.0 실제 실행 검사 — 2026-10-29

SketchUp Pro 2020 20.0.363 / Ruby 2.5.5, Probe·RBZ·MCP 모두 0.13.0. 사용자가 열고 실행을 허용한 작은 시험 모델에서 검사했다. 시작 상태는 Laura 1개, 정의 1개, 재질 8개, 태그 1개, 장면 0개, 선택 없음, 루트 편집, modified=false였다. 현재 채팅의 직접 MCP는 Transport closed여서 설치된 정식 MCP EXE에 검사 전용 STDIO 클라이언트를 연결했다. 임의 Ruby 실행이나 권한 자동 부여는 사용하지 않았다.

[원시 응답과 사용자 확인 기록](native-test-0.13.0-2026-10-29.json). 자동388개 검사와 실제 실행 결과는 서로 다른 증거다.

## 재현된 문제

### 툴바 아이콘 색상 미갱신

연결과 실행 허가가 켜진 fresh MCP 상태에서 사용자는 “둘 다 회색이거나 색이 안 바뀜”이라고 보고했다. 실제 SketchUp 2020에서 이미지 색 전환은 실패로 기록한다. Ruby double에서 아이콘 경로 설정이 바뀐 결과를 실제 그림 갱신 성공으로 취급하지 않는다. MF_CHECKED의 시각적 강조 자체도 이번 화면 캡처로 검증하지 못했다.

기존 구버전 API 제약 보고와 부합하지만, 현재 장비에서 대체 구현이 성공했음을 입증한 것은 아니다. 요구한 색 전환은 수정·재검사 대상이다.

### 3D DXF/DWG 내보내기 차단

materials=false로 새 DXF와 DWG 경로에 각각 한 번 내보냈다. 두 요청 모두 unsupported_export였다. 새 진단은 정확히 다음 부속 파일을 반환했다.

- sidecar_count: 1
- name: Audit report.txt
- directory: false
- truncated: false

내보내기의 단일 파일 계약이 이 부속 로그까지 거부하는 것이 차단 지점임을 확인했다. 진단은 동작했지만 CAD 내보내기 기능은 통과가 아니다. DXF 목적 파일이 게시되지 않았음을 확인했고 가져오기/왕복은 실행하지 않았다. 이 로그의 실제 내용·무해성은 검사하지 않았으므로 임의로 무시해도 안전하다고 판정하지 않는다.

## 미확정·미실행

- **긴급 정지:** 현재 모델에 묶인 오프라인 계산8개와20초 데모를 시작한 뒤 사용자는 “3번 버튼이 비활성이라 못 누름”이라고 답했다. 후속 조회에서 계산8개는 succeeded/effect=none/submitted=false, 데모는 completed였으며 authority=mcp였다. 작업 도중에 버튼이 비활성이었는지, 확인 시점에 이미 끝났는지는 구분하지 못했다. 취소 또는 긴급 정지에 의한 권한 회수 성공으로 판정하지 않는다.
- 화면 캡처가 FrameArrived/window capture timeout으로 실패했다. 접근성 읽기는 가능했지만 클릭은 coordinate input geometry unavailable로 거부됐다. 메뉴 진입을 시도했으나 정보창 동작은 사용자가 직접 확인했다. 이후 물리 Escape로 Computer Use가 중단되어 더 이상 화면 조작 도구를 호출하지 않았다.
- 도킹/숨김 후 앱 재시작 복원, 연결 해제·재연결의 버튼 시각 상태, 다른 실제 SketchUp 프로세스 작업과의 긴급 정지 격리는 남는다. 자동 double/Win32 두 peer 검사를 실제 화면 검사로 대신 판정하지 않는다.
- 지형 grouping=none의 면 방향·내부선 시각 검수, 교차선/개구부 개별 흐름, 단면 전체 장면 복원, 전체 IFC 속성 왕복, 실제2019와2026+ 전용 기능은 별도 검사 대상이다.

## 종료와 다음 작업

모델에 새 형상·정의·재질·태그·장면을 남기지 않았고 원본 모델 파일을 저장하거나 덮어쓰지 않았다. 기존 QA 기법의 검증 기록만 갱신되었으며 새 기법이나 활성본은 만들지 않았다.

검사 전용 MCP 클라이언트는 정상 종료했다. 그 뒤의 최종 연결 조회는 Bridge unavailable였고 프로세스 확인에서 SketchUp/Probe가 더 이상 실행 중이지 않았다. 연결 종료 후의 권한 상태는 관측하지 못했으며, 이를 긴급 정지 성공으로 해석하지 않는다.

우선 수정·재검사할 것은 아이콘 색 전환과 CAD의 Audit report.txt 처리다. 긴급 정지는 사용자 준비를 확인한 상태에서 작업이 실제 실행 중임을 함께 관측하며 다시 검사해야 한다. 이번 변경은 실기 기록만 추가하며 실행 파일/RBZ는 수정하지 않았다.
