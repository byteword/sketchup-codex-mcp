# 0.4.1 실제 모델 전환 시험 — 2026-10-28

사용자가 0.4.1로 교체한 뒤 실제 SketchUp에서 새로 만들기·시험 파일 저장·같은 파일 다시 열기를 수행했고, MCP 응답으로 전후 상태를 비교했습니다. 수정 기준은 로컬 커밋 `8a0cc0c`입니다. 이번 실기에서는 자동 검사나 형상 생성·이동을 실행하지 않았습니다.

## 환경과 식별값

중개 앱과 확장 보고 버전 모두 `0.4.1`, SketchUp `19.2.222`, Ruby `2.5.5`, Windows x64입니다. 아래 과정에서 동일한 프로세스와 `session_id`를 유지했습니다. 모델 ID는 가독성을 위해 앞 8자리만 표시합니다.

| 단계 | 문서 상태 | 모델 ID 앞 8자리 | 실행 권한 |
|---|---|---|---|
| 시작·수동 허용 후 | 제목·경로 없는 미저장 시험 모델 | `7465add3` | `mcp` |
| 파일 → 새로 만들기 직후 | 제목·경로 없는 새 시험 모델 | `3c3eff55` | `user`, `Model changed; control returned to user` |
| 새 시험 파일 저장·수동 허용 후 | `MCP_041_테스트.skp` | `3c3eff55` | `mcp` |
| 같은 파일 → 열기 직후 | 제목·경로가 저장 직후와 동일 | `e088dfc8` | `user`, `Model changed; control returned to user` |

새로 만들기에서는 같은 빈 제목·경로여도 문서 ID가 바뀌었고, 같은 파일 다시 열기에서는 동일 파일 경로여도 ID가 바뀌었습니다. 프로세스/세션을 재시작해서 ID가 바뀐 결과가 아닙니다. Ruby `object_id` 자체는 공개 도구 응답에 없어 비교하지 않았습니다.

## 항목별 판정

| 항목 | 확인 결과 |
|---|---|
| 0.4.1 연결 | 중개 앱·확장 버전, 모델/선택 조회 성공 |
| New 후 ID 갱신·허가 회수 | 위 첫 두 단계로 확인. 명령 번호는 `:1` 유지 |
| New 후 이전 ID 조회 | 모델 요약·선택 조회가 모두 `model_mismatch`로 거부 |
| New 후 이전 ID 변경 도구 | 박스 생성 **미리보기** 요청이 `model_mismatch`로 거부 |
| New 후 현재 ID 조회 | 사용자 제어 상태에서 모델 요약·선택 조회 성공 |
| New 후 허가 없는 변경 도구 | 사용자 제어를 확인한 상태에서 박스 생성 **미리보기**가 `authority_or_model_mismatch`로 거부 |
| 최초 시험 파일 저장 | 빈 경로에서 시험 파일 경로로 바뀌어도 모델 ID 유지. 저장 후 사용자가 실행 허가를 부여했으므로 저장 전후 허가 유지까지 판정하지 않음 |
| 같은 파일 다시 열기 | 저장 직후와 파일 경로·제목·프로세스·세션은 같고, 모델 ID만 새 값으로 변경. `mcp` → `user` 자동 회수 확인 |
| 다시 열기 후 이전 ID 요청 | 모델 요약과 박스 생성 **미리보기** 모두 `model_mismatch`로 거부 |
| 다시 열기 후 현재 ID 조회/미허가 요청 | 요약·선택 조회 성공, 박스 생성 **미리보기**는 `authority_or_model_mismatch`로 거부 |
| 시험 후 모델 상태 | `saved=true`, `modified=false`, 기본 인물 컴포넌트 1개, 선택 0개. 새 형상 없음 |
| 시험 후 명령 상태 | 다음 번호 `:1` 유지. 거부된 요청이 번호를 소비하지 않음. 최종 권한 `user` |

변경 도구는 `dry_run=true`로만 호출했습니다. 따라서 실제 형상 쓰기나 이전 lease 재사용의 전체 실기를 대신하지 않으며, 이번 확인은 문서 ID/실행 허가 사전 검사의 거부 경로입니다. 현재 모델 상태를 새로 확인한 뒤 각 요청을 보냈고, 알 수 없는 결과의 자동 재전송은 하지 않았습니다.

## 남은 조건

- 저장된 모델을 편집한 뒤 일반 저장, 다른 이름으로 저장할 때의 ID·허가 유지. 이번에는 미저장 모델의 최초 저장 후 ID 유지만 확인했습니다.
- 다른 시험 파일 열기, 연속 New/Open, 실행 중 데모·대기 명령과 전환의 경합, 다중 인스턴스/소유자와 이전 lease 거부의 실제 앱 시험.
- 신규 문서에서 새 허가 후 실제 변경 성공과 이전 결과 이력/중복 요청의 실기. 이번에는 현재 모델을 변경하지 않았습니다.

**판정:** 0.4.0에서 발견한 핵심 재현 조건인 새로 만들기와 같은 파일 다시 열기의 모델 ID 갱신·기존 허가 자동 회수가 실제 앱에서 확인됐습니다. 자동 회귀 137개와 별도의 증거이며 모든 저장·경합 조건의 통과로 확대하지 않습니다. [수정 설계](MODEL_IDENTITY.md), [전체 검증 이력](VALIDATION.md), [다음 기능 계획](FEATURE_PLAN.md)을 참고하세요.
