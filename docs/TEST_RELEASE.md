# 0.14.2 시험 배포 — 2026-10-30

최신 런타임은 `dist/sketchup-codex-mcp-0.14.2-test.zip` (5파일)이다. .NET 기본TLS가 VWorld에 연결하지 못하는 문제를 TLS1.2로 수정했다. VWorld 소스 애드온은 기존0.2.0을 그대로 사용한다. 실행 중인 사용자 설치 앱은 자동 교체하지 않았다.

`dist/vworld-massing-workflow.zip`은 별도 선택 소스 패키지이며, `dist/vworld-massing.probe-techpack`은 두 등록 기법의 공유 패키지다. [이번 실제18동 생성 결과·반복 실행법·제약](VWORLD_MASSING.md), [0.14.2 검사 기록](validation-0.14.2-vworld.json). 반복 스크립트는현재0.14.1 설치본에서도 TLS helper로 동작하며 기본은 plan-only, -Apply 지정시 새그룹 생성이다.

## 0.14.1 시험 배포 이력

최신 기본 런타임: `dist/sketchup-codex-mcp-0.14.1-test.zip` (5파일). 선택 VWorld 애드온: `dist/probe-addons-vworld-0.2.0.zip` (3소스). 기본 ZIP 안의 `dist` 폴더에 애드온 ZIP을 풀어 `SketchUpPipeProbe.exe`와 `AddOns` 폴더가 나란히 오게 한다. 작업본 `dist/AddOns/vworld`에도 같은 소스를 준비했다.

건물 높이·윤곽, 지적도 경계·지번, 주소→좌표 검색, 벡터 미리보기/GeoJSON 저장을 추가했다. 별도 브라우저의 지형 도구는 지점 또는 최대 10×10 격자 수치를 CSV로 내보낸다. VWorld 0.2.0의 manifest는 `probe-addon/2`이며 0.14.1 이상 호스트가 필요하다. 업데이트 후 소스 활성 체크를 다시 저장한다. [사용법과 데이터 기준](ADDONS.md).

지형은 SDK 타원체 기준 높이이며 VWorld 원자료 기준·변환·실측 정확도는 미검증이다. 사용자 인증키로 실서비스 건물/지적도/주소/지형 조회를 아직 하지 않았다. 브라우저 도구는 키를 별도 입력하며 Probe DPAPI 키를 파일로 넘기지 않는다. 로컬 파일의 도메인 인증 허용 여부도 실제 키 정책에 따라 확인해야 한다.

기본 ZIP 5파일·RBZ 51파일·애드온 3파일의 원본 바이트 일치와 추출 폴더에서 외부 DLL 없는 worker 실행을 검증했다. [패키지 검사](validation-0.14.1-package.json). 실제 설치 앱 교체·커밋·푸시는 하지 않았다.

## 0.14.0 시험 배포 이력

`dist/sketchup-codex-mcp-0.14.0-test.zip`은 기존처럼 EXE 2개·설정 2개·RBZ 1개만 담는다. VWorld 소스 애드온은 `dist/probe-addons-20261030-134222.zip`으로 따로 제공한다. **기본 ZIP을 푼 뒤 그 안의 `dist` 폴더에 애드온 ZIP을 풀어** `SketchUpPipeProbe.exe` 바로 옆에 `AddOns/vworld`가 오게 한다. 개발 작업본의 `dist/AddOns`에도 같은 애드온을 배치했다.

Probe의 **AddOns 설정 / 조회**에서 인증키·등록 URL을 입력하고 활성 체크와 설정 저장을 누른다. 기본값은 비활성이며 실제 키는 배포본에 없다. MCP를 새 EXE로 재시작하면 65개 도구를 불러온다. 키 없이 조회 성공으로 판정하지 않았으며 실제 VWorld 응답은 등록 후 확인해야 한다. [사용법](ADDONS.md), [패키지 검사](validation-0.14.0-package.json).

기본 ZIP 5파일, RBZ 51파일의 소스 바이트 일치, 선택 애드온 ZIP 2소스 일치와 추출 폴더에서 외부 DLL 없이 애드온 worker 실행을 확인했다. 실제 설치/실행 앱 교체·원격 배포는 하지 않았다. 아래는 0.13.0 이력이다.

## 0.13.0 시험 배포 — 2026-10-29

실제2020 검사 후 **아이콘 색 전환 실패**, **3D DXF/DWG의 Audit report.txt 부속 로그 거부**가 확인됐다. 정보창 닫기 후 연결/허가 유지와 고정69개·기법 native18케이스는 통과했다. 긴급 정지 취소와 도킹/재시작은 미확정이다. [실기 결과](MANUAL_RESULTS_0.13.0.md). 이 기록 추가로 EXE/RBZ를 다시 빌드하거나 교체하지 않았다.

MCP 도구63개. SketchUp4버튼 툴바와 기본 숨김 정보창, 현재 문서의 Probe 작업 상태/긴급 정지를 추가했다. 연결·권한 색상 표시, 대기 중 긴급 정지 비활성, 중지 시 권한 회수를 제공한다. [동작과 한계](FEATURES_0.13.0.md), [검증](VALIDATION.md).

자동 설치하거나 실행 중인 앱을 교체하지 않았다. **새 RBZ 설치 후 아이콘 상태 전환·도킹·보조창 실기 확인이 필요하다.** Probe와 RBZ를 함께 업데이트해야 기법 작업의 상태/정지를 사용할 수 있다.3D CAD 왕복 등 이전 버전의 미완료 실기는 별도로 남아 있다.

## 배포 파일

`dist/sketchup-codex-mcp-0.13.0-test.zip`에는 아래 실행 필수 파일 5개만 포함합니다. 문서·소스·테스트 도우미는 설치 ZIP에 넣지 않습니다.

- `dist/SketchUpMcp.exe`
- `dist/SketchUpMcp.exe.config`
- `dist/SketchUpPipeProbe.exe`
- `dist/SketchUpPipeProbe.exe.config`
- `dist/su_pipe_probe-0.13.0.rbz`

두 EXE의 파일 버전은 `0.13.0.0`, 제품 버전은 `0.13.0`입니다. 파일별 SHA-256은 저장소 루트의 `SHA256SUMS.txt`에 기록합니다. 로컬 빌드와 GitHub Actions의 빌드는 생성 시각 등에 따라 체크섬이 다를 수 있으므로 각 배포본에 맞는 기록을 사용합니다.

## 설치

1. 열려 있는 작업을 저장하고 SketchUp, 중개 GUI, MCP 서버를 종료합니다.
2. ZIP을 풉니다. 기존 MCP 등록 경로를 유지하려면 ZIP 안의 `dist` 폴더에 들어 있는 파일 5개를 현재 실행 파일이 있는 폴더에 복사합니다. 폴더 안에 `dist`를 한 번 더 만드는 일이 없도록 실행 파일 경로를 확인합니다.
3. SketchUp 확장 관리자에서 새 `su_pipe_probe-0.13.0.rbz`를 설치하고 SketchUp을 완전히 종료했다가 다시 엽니다.
4. 새 `SketchUpPipeProbe.exe`를 실행하고 SketchUp MCP 툴바1번으로 연결합니다.4번 정보창에서 버전 `0.13.0`을 확인합니다.
5. MCP 서버를 다시 시작하고 도구 63개가 노출되는지 확인합니다. 실행 파일 위치가 바뀌었다면 등록된 전체 경로도 수정합니다.

## 새 라이브러리의 첫 시험

먼저 연결 없이 패널/창 예제를 조회·저장하고 오프라인 검증/계획을 실행할 수 있습니다. 시험 모델에 기존 재질을 바인딩하고 `environment=native` 검증으로 임시 생성/abort·상태 복구를 확인합니다. 그 다음 작은 창 생성·교체·한 번의 Undo를 확인하세요. 패키지는 여러 기법 export 후 다른 라이브러리에 일부만 import해 목록과 의존성/기존 활성본 보존을 확인합니다. 작업 파일 수정·자동 초안 반영도 확인할 수 있습니다. [구체적인 절차와 한도](PROBE_LIBRARY_RUNTIME.md)를 따릅니다.

## 첫 시험

작은 시험 모델을 열고 그룹 내부 편집에서 나온 뒤 패널의 **MCP 명령 실행 허용**을 한 번 누릅니다. “이 시험 모델에서 일괄 실기 검사해줘”라고 요청하면 suite=all로 기능55개와 임시 형상 정리를 한 번에 확인합니다. 결과의 실패/생략·소요 시간·정리 여부를 확인합니다. 도형마다 응답하거나 Undo할 필요는 없습니다.

정보 조회·검색은 허가 없이 가능합니다. 개별 조작을 시험할 때는 “XY 평면에 가로 1000, 세로 2000 mm 사각형을 만들어줘”, “그 그룹을 3000 mm 돌출해줘”, “박스를 모델 Z축으로 30도 회전해줘”처럼 요청합니다. 각 요청은 최신 대상 경로·편집 위치와 새 명령 ID를 확인합니다.

속성·이동·생성·복제는 요청당 하나의 Undo 작업으로 묶습니다. SketchUp에서 Ctrl+Z로 요청 전체가 되돌아가는지 확인합니다. 선택·카메라 변경은 모델 Undo와 별개입니다. 장면은 카메라 전용이며 SketchUp2019의 장면 변경에는 같은 Undo 보장을 하지 않습니다. 잠긴 객체나 여러 배치가 공유하는 편집 상위 정의 등 지원하지 않는 대상은 거부합니다.

시간 초과 시 변경을 자동 재전송하지 않고 `sketchup_get_command_result`로 결과를 조회합니다. 같은 ID의 결과는 과거 실행 기록입니다. 사용자가 Undo한 뒤에도 이전 성공 기록이 남으므로, 같은 ID를 보내 재생성하거나 다시 이동시키지 않습니다.

## 검증의 범위

개발 자동 검사는 실제 Windows 통신 경로를 사용하지만 모델·형상·카메라·Undo·AppObserver 알림에는 대역을 사용합니다. 설치 후 `sketchup_run_self_test`가 실제 SketchUp API를 확인합니다. 한 aborted operation에서 검사하므로 개별 Undo·파일 전환·경합은 검증 범위 밖이며 [세부 범위](BATCH_TEST.md)에 명시했습니다. 과거 실제 앱의 확인 범위는 [0.4.0 결과](MANUAL_RESULTS_0.4.0.md)와 [0.4.1 결과](MANUAL_RESULTS_0.4.1.md)를 기준으로 합니다.
