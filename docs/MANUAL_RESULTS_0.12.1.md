## 발견 사항과 0.12.2 변경

- **종료한 스크립트 프로세스 조회 오류**: raw 검증 작업23d3ac6f-f2a3-4f31-8603-14460746dc84는 모델 전달 전에 library_error(“프로세스가 끝났으므로 요청한 정보를 사용할 수 없습니다.”)로 끝났다. 이후 별도 전체 검증은 성공했다. 소스의 HasExited 확인과 메모리 조회/Kill 사이 경쟁 조건을 수정했다. 자식 종료가 확인될 때만 관련 예외를 흡수하고, 살아 있는 프로세스의 오류·시간/메모리 제한 위반은 유지한다.15가지 조건을 결정적으로 검사했다. **그 당시 전체 스택이 없어 유일한 원인이라고 단정하지 않으며 수정본의 실제 Probe 재시험은 남아 있다.**
- **예제 계산 한도**: 기존1초 창 검증에서 budget_exceeded가 간헐적으로 발생했다. 시험용 창/raw/지형/텍스처 초안을5초로 조정한 뒤 위 범위가 통과했다.0.12.2는 배포 예제4개의 같은 한도를5000ms로 변경한다. 전역 최대치·메모리 제한은 유지하고 기존 사용자의 저장/활성 revision을 자동 변경하지 않는다.
- **3D DXF 내보내기**: 재질 true/false 두 요청 모두 “Exporter produced sidecar files; single-file export required”로 거부됐다. 후속 CAD 가져오기는 실행하지 않았다. 재질이 원인이라고 단정할 수 없다.0.12.2는 거부 시 부속 항목 수·이름·디렉터리 여부를 제한된 details로 기록한다(최대8항목/이름96자). 단일 파일 계약을 완화하거나 불완전한 파일을 게시하지 않는다. **3D CAD 왕복은 미통과다.**
- **0.12.0 복구 불일치**: 이번 새 모델의 여러 조건에서 재현되지 않았다. strict stamp 비교를 유지한다. 근본 원인 해결이나 이전 실패 모델의 복구를 입증한 것은 아니다.

분류 경로는 설치 SKC 및 [공식 ComponentDefinition API](https://ruby.sketchup.com/Sketchup/ComponentDefinition.html#get_classification_value-instance_method)의 타입 말단(IfcLabel)을 사용했다. CAD materials 옵션은 [공식 exporter 문서](https://ruby.sketchup.com/file.exporter_options.html)와 대조했다.

## 정리와 보존

시험 형상4개, 시험 장면2개, 스타일, 미사용 정의10개, 재질3개를 정리했다. 최종 모델은 처음과 같은 Laura1개/정의1개/재질8개/태그1개/장면0개/선택0이며 경계도 일치한다. 화면은 isometric으로 맞췄다. 모델은 modified=true이고 사용자가 저장한 원본 파일은 자동 덮어쓰지 않았다.

스타일/정의 purge는 각각 자동 승인 검토에서 차단된 뒤, 정확한 시험 대상과 범위를 확인하고 사용자의 명시적 허용을 받아 실행했다. 실행하지 않은 거부 요청을 native 실패로 집계하지 않는다.

C의 dist/native-acceptance-0.12.1-20261029에 saved-copy.skp, classified.ifc, native-view.png를 보존한다. 기본 라이브러리의 QA초안5개와 선택 가져오기용 lib-aa5ef23cabae49a2a9935c903812d41c는 미활성 상태로 남는다. 일반 설치 예제와 활성 기법을 덮어쓰지 않았다. 설치 앱은0.12.1이며0.12.2 ZIP은 별도 검증 후 제공한다.

검사 중 행동별로 허용되지 않는 scene 옵션, 조회 limit0/50, create_library에 임의 ID를 넣은 호출은 변경 전에 거부됐다. 이후 계약에 맞게 수정했다. 초기 command1/3/5/6/7 결과는 뒤늦은 조회에서 캐시 만료였으며 보존된 최초 job/응답으로 판단했다. 만료 명령을 재실행하지 않았다.
